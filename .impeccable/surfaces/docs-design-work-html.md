# 作品详情

**模式**：Operate。只按桌面宽度设计，窄屏不坏即可。
**为谁**：作者自己（一人公司，用 Claude 做内容，发到自己的多个平台账号）。以后给同类创作者：从"一条视频、一种语言、两三个平台"到"多支成片、多语言、七八个平台"都是同一个结构。
**解决什么**：一个作品的全部：每支成片发到了哪里、等不等我确认、结果如何、出过什么事。
**怎么做**：和"今天"同一个成片面板：没确认的成片在这里确认，发过的成片每行换成结果；右侧成片列表与这支成片的经过；出问题时一块红底说明和处理按钮；下面是这支成片各平台和平时的对比。
**成功长什么样**：不用去任何平台后台，就能回答"这支发了吗、发得怎么样、哪里出过问题"。
**明确不做**：改视频本身、跨作品比较（数据页）。
**数据从哪来**：`vk work show <id>`：成片、平台稿、run 事件、快照。
**依据**：`docs/PRD.md` v0.2、`docs/design/FLOW-v2.md`。硬规则：没有人确认，一条都不会发。

## Direction contract

THESIS：安静的工作台。一屏只回答一个问题，主操作只有一个；数字永远和这个账号自己的平时比。参考 Things 3（今天的安静）、Linear（一行一个对象、状态小而清楚）、YouTube Studio（和平时比）。
OWN-WORLD：暖白场地 #fafaf8、白色面板、发丝线；墨色 #1a1c1f 是唯一的主按钮色；黄 #ffd84a 只表示"等你处理"，红 #c4321c 只表示"出了问题"，绿 #0f7a4a 只表示"比平时好/正常"。系统字体，表格数字等宽对齐。不用装饰性隐喻、卡片墙、跨平台相加的大数字。
FORM：左 208px 侧栏四项（今天、作品、数据、系统）+ 右侧单列内容；只按桌面宽度设计，窄屏不坏即可。手机上只有飞书。
FINISH：unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and the baseline screenshots in docs/design/screenshots/v2/.
FIRST VIEWPORT：返回链接、标题、入库时间、状态；成片面板 + 右侧成片列表与经过。
SIGNATURE：经过用一句人话一行，失败的一行是红字。

## 确认时看得到、改得了发出去的内容（#175，ACC-v2-copy-04）

**问题**：确认面板只显示标题和时间，每个平台的正文和话题看不到；确认的时候看不到发出去的内容，这个确认就形同虚设。所有者 2026-11-16 定：文案在入库时由 Claude 写好，确认时要能看、能改。
**对象模型不变**：一条平台稿 = 一个平台 + 标题 + 正文 + 话题 + 时间。正文、话题和标题一样是这条平台稿自己的（人改过的优先），不是作品的、也不是平台的。
**页面职责**：仍然一页一个任务——确认这支成片。看正文不另开页：每行点标题就地展开，看到「正文」「话题」；点「改」，这一行变成可编辑：标题、时间、正文、话题。小红书那一块同样处理（「看正文和话题」、「改」）。
**状态词表**：正文为空写「没有正文」，话题为空写「没有话题」，灰字，不报错、不阻止确认。超过平台限制时，保存被拒并说是哪个平台、哪个字段、限多少（不悄悄截断）。
**明确不做**：不在面板里重写文案（文案由 Claude 在入库时写）；不做富文本、不做逐平台字数计数条（限制由保存时校验给人话）；TikTok 官方接口那块的文案另有自己的设置面板，不动。
**数据从哪来**：`/api/works/:id` 每条平台稿已带 `body`、`tags`、`empty`；保存走 `publish.edit`（`title`、`body`、`tags`、`at`，已有参数不变）。
**飞书**：确认卡片每行在标题、时间下面带正文前 3 行和话题；为空同样写「没有正文」「没有话题」。卡片里不改正文（到网页上改）。

## v3（2026-11-18，所有者定）：改内容、现在发 / 预约发、取消编辑

覆盖上面「确认时看得到、改得了」一节里和它冲突的说法（逐行就地编辑、每行一个「好了」）。

**所有者踩到的三个问题**：改完文案保存，被提示「时间不能是过去的」（建议时间早就过了，而保存把旧时间一起交了上去）；没改好想退出，没有取消；一个作品发七八个平台，想把共同的地方一次改掉、再个别调，做不到。

**对象模型（先定这个）**
- 文案分两层：**通用文案**属于「这支成片的这个语言版本」（标题、正文、话题）；每条平台稿按字段要么**跟通用**，要么**单独写**。中文版的通用管小红书、抖音、视频号、B站、官网，英文版的管 TikTok、YouTube。
- 改通用，跟通用的平台一起变；单独写过的不变，并且当场说出是哪几个没变。单独写的字段随时可以「改回跟通用」。
- 时间不属于文案。发布方式是二选一：**现在发**（没有时间）或**预约发**（有时间，必须在将来）。**只在确认时整批选**，编辑里只改时间（所有者 2026-11-18 定，避免整批和逐条互相覆盖）。

**页面职责**
- 看的时候：和 v2 一样的成片面板。底栏多一个二选一「预约发 / 现在发」，主按钮的字跟着变：「确认这 6 条，按时间发」/「确认这 6 条，现在发」。
- 改的时候：点面板标题旁的「改内容」（或某一行的「改」）进入编辑。编辑是面板的一个状态，不另开页、不弹窗：上面是通用文案，下面每个平台一行、可展开；底栏是「取消」和「保存改动」。
- **取消**：没改过直接退出；改过了，底栏就地问一句「放弃这 N 处改动？」。Esc 等于取消。离开页面前有未保存的改动要拦一下。
- **保存**是一次提交：要么全部存上，要么都不存。保存不会顺带提交时间，除非你动了时间。
- 已确认、还没发的（按时间发的）也能改，保存后仍按原来的时间发；编辑里不能把它改成现在发。已经发出去的、正在发的不能改。

**状态词表**
- 字段旁：`跟通用`（灰字）/ `单独写的`（墨字）+ 「改回跟通用」。
- 平台行摘要：`和通用一样` / `标题、正文是单独写的`。
- 时间：`现在发` / `今天 21:00` / `原定昨天 20:00，已过，顺延到今天 20:00`（黄点，系统自己给出新时间，不要求人去改）。
- 超限：在那个字段下面当场说「抖音的标题最多 30 字，现在 34 字」，并给「给抖音单独写一个」；不悄悄截断，保存按钮在解决前不可用并说明还差哪一处。
- 时间碰到平台规则：在时间下面说「小红书今天已经排了 1 条，最近能排明天 20:00」+「用这个时间」。

**明确不做**：改视频本身；富文本；在编辑里重新让 AI 改写（以后再说）；改已发布的内容；跨成片的通用文案（每支成片的内容本来就不同）。
**数据从哪来**：读 `work.show`（每个语言版本带通用文案和 `rev`，每条平台稿带哪些字段是单独写的、`timing`、`suggestedAt`）；保存走 `cut.edit`（ADR-0005 §3.4）。
**页面上不出现命令。**
