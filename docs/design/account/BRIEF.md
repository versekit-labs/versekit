# Hifabu 账号：任务书与结构（2026-11-24）

所有者 2026-11-24 定：在 hifabu.com 上做一个最简单的账号系统。用户能登录、下载发布机程序、安装插件；插件和发布机都用这个账号登录。两个人（所有者和爱人）各用各的账号，共用一台中转。

可点的设计稿：[proposals.html](proposals.html)（直接用浏览器打开）。**状态：所有者 2026-11-24 定稿。**相关：[../handoff/BRIEF.md](../handoff/BRIEF.md)（交给发布机，插件用的就是这个账号）。

## 0. 这次定了什么、推翻了什么

- **重新打开 11-18 定的「SaaS 先放一放」，但只做最小一块**：账号、下载、插件登录、发布机登录。不做：每个用户一个库、收费、对象存储、网页版工作台、多人协作。
- **登录方式**：Google 登录（第一批）和邮箱验证码登录（第二批）。**不设密码**，所以没有找回密码。取代 ADR-0005 §5 的「邮箱 + 密码」和「邀请码注册」。
- **注册开放，传片（中转）按人开通**：新账号能登录、下载、装插件，按单机用；分两台电脑要用的中转，由所有者在管理页给指定账号开通。取代邀请码。
- **不变**：默认单机，单机不需要账号（ADR-0005 §15 第 7 条）；发布前必须人确认；平台登录只在发布机上；界面上不出现命令。

## 1. 任务书（一页一个任务）

| 页面 | 为谁 | 解决什么 | 成功长什么样 | 明确不做 | 数据从哪来 |
|---|---|---|---|---|---|
| **登录** `hifabu.com/login` | 第一次来的人和回来的人，同一个入口 | 进到自己的账号。没有账号就当场建 | Google：两次点击进来。邮箱：填邮箱、填 6 位码，30 秒内进来 | 密码、找回密码、邀请码、手机号、微信登录 | `session.create`；Google 授权；邮件验证码 |
| **接入机器** `hifabu.com/link` | 刚在一台电脑上点了「登录 Hifabu」的人 | 确认「是我要把这台机器接到我的账号上」 | 看清是哪台机器、它能做什么不能做什么，核对码一致，点「允许」，那台电脑自己继续 | 在这页填任何东西 | `device.link.*`（ADR-0005 §6） |
| **我的 Hifabu** `hifabu.com/account` | 已登录的人 | 拿到程序和插件；看到自己接了哪些机器；知道传片开没开通 | 新用户 3 分钟内下载、装好；丢了电脑的人能把那台机器退出 | 作品、排期、数据（这些在本机的工作台上，不在网站上）；改头像昵称 | `device.list`、`relay.grant.status`、发行清单 |
| **管理** `hifabu.com/admin` | 所有者一个人 | 决定谁能用中转、各用多少 | 有人申请时一眼看到，点一下开通 | 看用户的作品和文案；替用户操作 | `user.list`、`relay.grant.*`、中转用量 |
| **本机系统页里的「Hifabu 账号」一段** | 装了程序的人 | 把这台机器登录到账号；知道不登录也能用 | 点「登录」，浏览器里点「允许」，回来已登录 | 在本机填密码或令牌 | `cloud.status / login / logout` |
| **Claude 里的登录** | 在制作机上用插件的人 | 第一次「交给发布机」时登录 | Claude 说一句、开一个浏览器页，点允许后接着交，不用重说 | 让人抄令牌 | 同上 |

## 2. 结构

### 2.1 对象

- **Hifabu 账号**：一个验证过的邮箱。Google 登录和邮箱验证码登录，邮箱相同就是同一个账号。
- **机器**：属于一个账号；角色是「制作机」（Claude 插件）或「发布机」；有名字、最近在线时间；发布机还有出口位置。
- **传片开通**：账号上的一个开关加一个容量上限。只有开通了，这个账号的机器才能用中转。
- **投递**：记在账号名下。只有同一账号的发布机拉得到（解决两个人共用中转会互相拉走的问题）。

### 2.2 词表（界面上的说法）

| 说 | 不说 | 原因 |
|---|---|---|
| Hifabu 账号 | 账号 | 产品里「账号」已经指小红书、抖音这些平台账号，必须带前缀区分 |
| 机器；制作机、发布机 | 设备、executor、maker | — |
| 两台电脑之间传片；传片 | 中转、relay | 用户不需要知道有一台中转服务器 |
| 接入、允许 | 配对、授权 | — |
| 退出这台 | 吊销令牌 | — |

### 2.3 谁在哪

```
hifabu.com（首尔，走 Cloudflare 隧道；只有小请求）
  账号、会话、机器、传片开通；登录页、接入页、我的 Hifabu、管理
  安装包和更新文件放 R2

中转（volc1，现有 packages/relay）
  只认 hifabu.com 签发的机器令牌；按账号存投递、算用量
  视频不经过 Cloudflare（免费版单个请求上限 100MB，成片最大 188MB）

制作机 / 发布机
  登录后拿到机器令牌和中转地址，自己不用填任何地址
```

### 2.4 技术要点（给实现单）

- 无运行时依赖。账号服务是同一个仓库里的新包（暂名 `packages/cloud`），控制库用 `node:sqlite`：`user`、`identity`、`session`、`login_code`、`device`、`relay_grant`。
- **机器令牌**：hifabu.com 用 Ed25519 私钥签（`node:crypto`），内容是账号 id、机器 id、角色、能不能用中转、容量上限、1 小时过期。中转只拿公钥离线验，不用和首尔实时通信。机器用长期的刷新凭证每小时换一次；「退出这台」后刷新被拒，最多 1 小时内失效。
- **Google 登录**：授权码 + PKCE，只要 `openid email`（2026-11-24 按隐私政策去掉 `profile`）。仓库里 `adapter-youtube/src/pkce.mjs` 可以参考。
- **邮箱验证码**：6 位数字，10 分钟有效，错 5 次作废；按邮箱和 IP 分别限速；库里只存哈希。发信是配置（SMTP 或一家发信服务的 HTTP 接口），不引入 SDK。
- **会话**：HttpOnly、Secure、SameSite=Lax 的 cookie；改状态的请求校验 Origin（ADR-0005 §5 不变）。
- **命令**（CLI 完整律，只在 `commands.mjs` 定义一次）：本机 `cloud.login / cloud.logout / cloud.status`；账号服务上 `device.list / device.revoke / relay.grant.request / relay.grant.set / user.list`。不用 `account.*`，它已经是平台账号的命令。
- **中转**：投递和成片按 `账号 id/` 分目录；超过容量上限拒收并说还剩多少；现有的两个固定令牌保留到所有者的两台机器换成账号登录，然后删掉。
- **隐私**：库里存邮箱、Google 的用户 id、机器名、出口位置。要有一页隐私政策（Google 登录的要求），要备份控制库。

## 3. 状态

| 页面 | 状态 |
|---|---|
| 登录 | 初始；验证码已发；码不对；码过期；试太多次；Google 那边取消了；从接入页被带来（上面多一句「登录后继续接入『书房的 Mac』」） |
| 接入机器 | 等你允许；接上了；已拒绝；过期（10 分钟）；没登录（先去登录再回来） |
| 我的 Hifabu | 新账号（没有机器、传片没开通）；已申请开通；已开通（用量条）；快满（黄）；满了（红） |
| 本机「Hifabu 账号」 | 没登录（说明不登录也能用）；等浏览器里允许；已登录、传片没开通；已登录、传片已开通；连不上 hifabu.com（已登录的照常用，说明上次核对时间） |

## 4. 分批

**第一批（约 6 单）：所有者和爱人能用**

1. 账号服务：控制库、会话、Google 登录、登录页。
2. 接入机器：接入页、本机 `cloud.login`、机器令牌签发和刷新、我的机器、退出这台。
3. 中转认账号令牌：投递按账号分、容量上限、开通开关；所有者现有两台机器迁移。
4. 我的 Hifabu：下载、插件安装那句话；管理页。
5. 本机系统页「Hifabu 账号」一段；中转地址由登录带下来。
6. 插件：技能加登录（和「交给发布机」方案 A 合成一单或紧接着做）。

**第二批（约 1.5 单）：国内用户能注册**

7. 邮箱验证码登录和发信；QQ、163 邮箱到达率实测。

**所有者要做的**：在 Google Cloud 建一个 OAuth 应用，把 client id 和 secret 交给部署；第二批前选一家发信服务，给 hifabu.com 加 DNS 记录。

## 5. 所有者 2026-11-24 定的

1. **下载不用登录。** 单机本来就不需要账号。
2. **每个账号的传片容量 10GB。** volc1 可用约 33GB；发完 7 天自动清。
3. **有人申请开通，只在管理页上看。** 不发飞书。

## 6. 还没解决的

- 制作机上要先有 versekit 程序，插件才能调用。装插件时发现没有，要不要由插件自己装上：建议要，和发布机用同一个安装包。
- 发布机到 volc1 的下载速度还没实测（见 handoff/BRIEF.md §2）。
- Google 的同意屏幕如果要显示 Hifabu 的标志，要过品牌核验；先不放标志。
