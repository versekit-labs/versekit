2026-11-18，设计会话整理。给协调器和实现 worker。v2 的 `HANDOFF.md` 仍然有效，本篇只写这一版变了什么；冲突时以本篇为准。

这一版把三件事合在一起做（所有者 2026-11-18 定）：

1. **ADR-0004 里还没做的**：用户、登录、邀请、设备、用户管理。
2. **ADR-0003 的验证计划**：11-17 做的中转（`ACC-relay-*`，volc1）只是其中「投递文件」的最小一步；云端排期、租约、绑定、协议版本还没有一条做，原样纳入验收。
3. **所有者这次提的七条**：研发架构把关；界面不出现命令；改内容分现在发和预约发、能取消；通用文案加各平台单独改；实现没有达到设计的地方；制作机上传用 plugin；发布机的出口 IP 和位置。

## 1.1 和 11-17 上线的中转是什么关系

main 上已经有中转（`packages/relay`，部署在 volc1，`vk work push` → `vk relay serve` → 发布机后台拉取入库，见 ACCEPTANCE「制作机 → 云端中转 → 发布机」一节和 `docs/deploy-relay.md`）。v3 不推翻它，而是在它上面长：

| 现在的中转 | v3 变成 | 哪一单 |
|---|---|---|
| 推送、拉取各一个共享 token，手工 `vk relay connect <地址> --token` | 设备码配对，每台设备一个令牌，绑定用户和角色 | 第 8 单 |
| 云端只存文件和投递清单 | 云端是控制面：每个用户一个库、排期、租约 | 第 9 单 |
| 文件存在 volc1 磁盘上（出口约 0.11MB/s，3 支视频下了 6 分钟） | 对象存储，签名地址直连；发布机预取 | 第 11 单 |
| 部署在 volc1（国内） | 云端放国外（所有者 11-18 定） | 第 9 单 |
| 制作机跑 `vk work push` | plugin 在后台调用同一条命令 | 第 12 单 |

在第 8、9、11 单合并之前，**volc1 上的中转照常运行，不要停、不要拆**；所有者现在每天靠它把视频送到发布机。迁移时新旧并存一段，发布机两边都能拉，确认新的一条路跑通后再下线 volc1 的站点（只动 versekit 自己的站点块，不碰 volc1 上别的服务）。

第 5 单（界面去掉命令）碰到中转时：系统页里「中转连接状态、上次拉取、正在下载的进度」（ACC-relay-04）保留，挪到「设备」分段发布机那一行里显示，界面上不写 `vk relay …`。

## 4. 实现没有达到设计的地方（2026-11-18 审计）

独立 agent 把实现跑起来和定稿并排比过。结论：组件做得准，整体观感差在三处。

1. **旧样式没清**。`packages/web/public/app.css` 前 199 行是 v1 的样式，它的 `body`、`.nav a`、`:focus-visible`、`::selection` 仍然生效：底色成了 `#f4f4f2`（应为 `#fafaf8`），导航项 42px（应为 34px），没有字体平滑和等宽数字，按钮里的字是 Arial，焦点环是琥珀色。这是每一页都「不像」的主因，也最好修。
2. **数据页没做**，是一个写给开发者看的占位面板；「今天」还多了一个指向它的「看全部」。
3. **封面全是灰块**。接口已经返回了封面，页面没用。

另外：侧栏「今天还能发 26 条」是跨平台相加，违反设计；「接入账号」「再试一次」用了墨色主按钮；已发布行的时间列用的是计划时间。

**设计自己的缺口**（这一版已补）：报错长什么样、能不能取消、打字到一半会不会丢、素材读不到、没有建议时间。这些以前没画，实现各自补了，风格不统一。还有一条：v2 定稿的「今天」自己就有三个墨色主按钮，违反「一屏一个」；v3 改成只有确认是墨色。

实现里新增而设计没有的：TikTok 官方接口的设置面板（英文按钮、墨底标签、进度条）。这一轮没有重新设计它，下一轮单独过。

## 6.1 独立评审之后留下的问题（没在这一轮解决）

这一版的原型由独立 agent 实际点过一遍，3 个会误导人的问题和大部分别扭的地方已经改掉并进了口径（ACC-v3-edit-05/06/08、ACC-v3-time-07、ACC-v3-egress-03/05/06/07、ACC-v3-user-05、ACC-v3-device-07）。下面几条是对象模型层面的，没有在原型里解决，实现前要有结论：

1. **「继续用新位置」是按在发布机上的，改的却是这台机器上所有账号的基线。** 现在的设计就这么做（一台机器一个位置，逐个账号确认太烦）。如果以后一台发布机上有分属不同地方的号，要重新想。
2. **通用文案能管几个平台，取决于入库时怎么写。** 入库技能要改成「能共用的只写通用」（ADR-0005 §9）。改通用时要不要提供「同时覆盖单独写的」，这一轮没做，先看用起来缺不缺。
3. **底栏「预约发 / 现在发」是整批设，编辑里是逐平台设，整批会盖掉逐平台的选择。** 混合状态下底栏两个都不亮、主按钮写「开始发」，还不够清楚。
4. **只用网页版 Claude 的用户接不上**（读不了本机文件）。页面上还没有分流的一句话。
5. **邀请链接在手机上打开**：第 2 步「打开安装页」在手机上没有意义。现在只加了「复制安装页的地址」和一句「把地址发到那台电脑上打开」。
6. **新用户进「今天」而一个作品都没有**的样子没画（作品页的空状态画了）。
7. TikTok「填应用凭证」仍然是一个技术门槛（要去开发者后台拿 client key / secret），这一轮没有动。
