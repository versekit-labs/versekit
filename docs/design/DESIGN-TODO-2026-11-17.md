## 一、系统页：把实现时补出来的东西画进设计稿（设计稿要追上实现）

1. **接入账号**：设计稿里没有。实现是在账号表下面放一行「平台下拉框 + 账号名输入框 + 接入账号按钮」。要定：放在哪里、长什么样；下拉框有三种状态（没装适配器 / 这个组的平台都接上了 / 有可接的平台）分别怎么显示。
2. **登录进行中的行内状态**：「等你扫码 / 等你登录」，这一行带「取消」和「我扫好了 / 我登录好了」两个按钮；失败时这一行显示红字原因。设计稿里只有「等你扫码」和「我扫好了」。
3. **TikTok 官方接口那一行**：没有应用凭证时，要在这一行填 client key 和 client secret（secret 不回显）；有凭证、没授权时，显示「Connect TikTok」主按钮。现在这个主按钮是墨色实心的，和别的行的「重新登录」文字链接不一样，要定统一规则。
4. **账号组表**：实现里第二列是「N 个 · 平台名」，设计稿是组的说明文字；当前组还多了一个「改名」。二选一定下来。
5. **侧栏底部状态摘要**：「1 个账号登录正常，3 个要处理」太长会折行（见状态截图左下角）。

## 二、系统页：正在做 / 马上要做的功能，需要先有设计

6. **退出登录 / 换号**（#220）：每个网页登录账号那一行加「退出登录」，作用是清掉这个账号的浏览器登录数据，然后可以换号。要定：放在哪里、要不要二次确认、退出后这一行长什么样。
7. **防串号提示**（#220）：登录到的平台账号已经接在别的组上时，不算登录成功，在这一行显示「这个小红书号已经接在「AssureLane」的 @AI 上；要接另一个号，先退出登录，再扫码或短信登录另一个号」。要定这条提示的样式。
8. **扫码说明**：扫码登录的是手机 App 上当前的号；要接第二个号，得先在 App 里切换账号，或改用短信登录。这句话放在哪里，用户才会在扫码前看到。
9. **自动更新**（#217，正在验收）：「发布机」一块加了当前版本、上次检查时间、自动更新开关；刚更新过时多一行「已更新到 <版本>（时间）」，附最多 5 条更新内容。自动更新失败会出现在「最近出的问题」里。设计稿里这些都没有。

## 三、要所有者拍板的产品问题（设计前先定）

10. **网页上还要不要能上传素材 / 新建作品？** 旧的发布台已删，现在入库只能用 `vk work add` 加 `vk plan apply`，或者让 Claude 用入库技能来做。v2 的设计是「网页只确认，不上传」。如果要能上传，就要设计作品页的入口和流程。
11. **登录方式要不要在网页上二选一？** 小红书支持扫码、短信、打开登录窗口三种，现在系统页只有「打开登录窗口」这一种。要不要让用户选？
