# 设计验收

设计方（本分支）只做两件事：**定稿**与**验收**。实现由另一个 session 在 `packages/` 里做。
这份文件是验收口径，验收人只认这里写的东西。

## 一、验收怎么跑

```bash
# 1. 起真实服务（实现方负责）
npm run serve                      # http://127.0.0.1:8787

# 2. 机械验收（一条命令）
npm run design:accept -- --url http://127.0.0.1:8787

# 3. 全量门禁（实现方合并前必须自己跑过）
npm run ci
```

> 页面路径映射写在 `scripts/design-accept.mjs` 的 `PAGES` 表里（`/accounts`、`/plan`…）。
> 实现方若改路由，必须同步改这张表并在 PR 说明——验收脚本以它为准。

`design:accept` 会依次检查并给出通过/打回：

| 检查 | 判定 |
|---|---|
| 九个页面在真实服务上返回 200 | 缺一个就红 |
| 页面**不再引用** `store.js`（原型假数据） | 引用了就是没接真实数据 |
| 页面引用了 `api.js` 或含 `fetch('/api` | 没有就是硬编码 |
| `design-check --url` 通过（任务书/导航/死链/检测器/触控/溢出/hidden） | 任一失败即打回 |
| 每页的任务书存在 | 缺一页即打回 |

## 二、逐页验收项

每页都要过三件事：**数据来自 `/api`**、**每个动作有对应命令**、**空/错/权限三态真实**。

### 账号页 `account-wall.html`
- 只显示**当前账号组**的五个平台槽位；未接入的显示缺口与添加入口。
- 点账号行，详情在组内就位；主动作指向具体账号。
- 空组：五个缺口 + 一句引导，不能白屏。
- 命令：`vk account list --group <g>`、`vk account reauth <id>`、`vk account remove <id>`

### 选择账号组 `groups.html`
- 首次进入无当前组时落到这里；选组后所有页面跟着变。
- 新建组后进入空组，不报错。
- 命令：`vk group list`、`vk group add`、`vk group use`

### 矩阵总览 `matrix.html`
- 跨组只读；点格子进入对应组。
- 页面明确写"只读"，不能在这里改数据。

### 发布台 `publish.html`
- 只列**当前组**账号；已失效的账号不可选并说明原因。
- 平台差异字段只出现在真正不同的地方；预演列出将发生什么。
- 发布后生成 work + 多条 publish，状态可查。
- 命令：`vk publish <asset> --group <g> --to ... --schedule ... --dry-run`

### 发布计划 `calendar.html`
- 一条排期 = 一个作品一张卡，卡上带该作品要去的平台；**不要拆成平台碎片**。
- 周/月/列表三视图；手机默认列表。
- 改期 1 步可达（快捷项），保存有 toast + 撤销；过去时间拦截；撞车在保存前提示。
- 撞车必须在卡片上有标记，不能只在摘要里报数。
- 空档行可逐日选择。
- 命令：`vk schedule list --group <g> --from --to`、`vk schedule move`、`vk schedule cancel`

### 作品详情 `work.html`
- 每个数字旁边有来源与时间；采集缺口要画出来。
- 平台级状态逐平台显示，不用一个状态盖住全部。

### 总览 `overview.html`
- 数字带口径（作品数 vs 平台发布数分开）；跨组汇总只读。
- 数据新鲜度面板与账号页一致。

### 任务与日志 `runs.html`
- 失败条目就地展开现场：错误码、平台原文、尝试次数、任务号。
- 重试有上限；不静默放弃。
- 命令：`vk run list`、`vk publish retry`

### 添加账号 `add.html`
- 组已锁定；已接入平台灰掉并说明被谁占用。
- 完成回到账号页能看到新账号。
- 命令：`vk account add --group <g> <platform>`

## 三、数字一致性（最容易糊弄的地方）

同一组、同一时间范围，三处必须相等：

```
页面显示  ==  CLI --json  ==  /api 返回
```

抽查三条：
```bash
vk schedule list --group ai --from 2026-11-01 --to 2026-11-30 --json | jq '.works | length'
curl -s 'http://127.0.0.1:8787/api/schedule?group=ai&from=2026-11-01&to=2026-11-30' | jq '.works | length'
# 与计划页摘要里的「N 个作品」对照
```

## 四、判定

| 结论 | 含义 |
|---|---|
| **通过** | `design:accept` 全绿 + 逐页项全过 + 数字一致 |
| **打回** | 任一机械项失败，或逐页项缺失，或数字对不上 |
| **有条件通过** | 只欠非阻塞项（如 hover 预览、拖拽改期），需在 PR 里列出并登记 |

打回时验收意见写到 PR 评论，格式：`[打回] 页面 / 验收项 / 实测 / 期望`，一条一行，实现方逐条回复。

## 五、不在验收范围

视觉风格的主观偏好、动效手感、文案润色——这些在设计阶段定稿，验收只查"是否照做"。
要改设计，先改 `DESIGN.md` 与对应 surface brief，再改实现；反向操作一律打回。
