# 飞书卡片 JSON（草稿）

**状态**：2026-11-15 用机器人往所有者的飞书发过一次，三张卡片飞书都接受了（结构合法）。手机上的手感、表单提交后回调里的字段名还要在实现时核对。示意图见 `../feishu.html`。

发的时候踩到的一条：表单里的"重置"按钮不能带回调（飞书报 `form reset action not support behaviors`），所以"取消"放在表单外面，是普通按钮。

| 文件 | 时刻 | 说明 |
|---|---|---|
| `confirm.json` | 确认一支成片 | 每个平台一行；按钮：这支先不发 / 改标题或时间 / 确认这 N 条，按时间发 |
| `confirm-edit.json` | 改标题或时间 | 上一张卡片原地换成表单；每条一个输入框和一个时间选择器 |
| `confirm-xhs.json` | 小红书单独确认 | 三个按钮：我自己发 / 现在发 / 按建议时间发 |

约定：

- `{{...}}` 是通道层渲染时填的变量。平台行按这支成片实际有几条平台稿生成，不是固定 6 行。
- 每个按钮的 `value.cmd` 是一条 `vk` 命令（三端一致律）：卡片回调只把它交给 core 执行，不自己改数据。`publish.approve`（人确认后进队列）、`publish.skip`、`publish.now`、`publish.manual`、`publish.edit` 是**待新增**的命令；现有的 `publish.confirm` 是另一个意思（notify 模式下确认已在 App 里发完），不要混用。实现时按钮数据还要带 `exp` 和幂等 `key`（见 `packages/core/src/notify.mjs` 的 `executeAction`）。
- 点完后用回调返回的新卡片原地替换（标题变灰、按钮消失），不能重复点。
- 账号组多于一个时，标题前加组名前缀；只有一个组时不加。

实现时要核对的：机器人上传视频消息的大小上限；表单容器里时间选择器在手机飞书上的手感；回调 3 秒内返回的要求。
