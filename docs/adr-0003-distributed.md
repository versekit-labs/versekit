# ADR-0003：云端控制面 + 制作机 + 发布机

**状态**：提议（2026-11-15）　**决策人**：产品 + Claude
**修订**：BLUEPRINT §3.1 进程模型（"单守护进程 + unix socket，Web 仅 127.0.0.1"）
**影响**：内核的部署形态、`vk` CLI、队列领取方式、账号与机器的绑定、文件存储

---

## 1. 背景

用户的工作方式（2026-11-15 确认）：

- **做视频**在一台电脑上：英国的 Mac mini，用 Claude Code 制作。这台也是开发机。
- **发视频**在另一台电脑上：和手机同网的 Mac，常开。
- **看内容、拍板**在手机上，通过飞书；坐在电脑前时用 Web。
- 有一台国内云服务器 `volc1`（火山引擎，4 核、4GB 内存、40GB 硬盘、Node 22），还有已备案的域名 `fangyouxi.cn`。

两条事实约束：

1. **国内平台的账号只能在和手机同网的电脑上操作**（11-14 小红书处罚的根因）。所以发布不能放在云端，也不能放在制作机上。
2. **国内服务器访问不了 YouTube、TikTok 的接口**，公众号接口则要求固定的白名单 IP。不同的发布任务天然要在不同的机器上跑。

trustbridge 的视频工厂把这三件事都塞在一台机器上，靠飞书多维表格驱动，没法分享给别人。versekit 要把它拆开。

## 2. 决策

### 2.1 三个角色，一套代码

| 角色 | 跑在哪 | 做什么 | 不做什么 |
|---|---|---|---|
| **云端**（`vk serve --role cloud`） | volc1 | 唯一的数据库；作品库、Web、飞书；排期与派活；状态机与事件；LLM 分析；需要国内网络或固定 IP 的发布（公众号草稿箱） | 不开浏览器，不存任何平台的登录态 |
| **发布机**（`vk serve --role executor`） | 和手机同网的 Mac | 绑定账号的登录、发布、采集（浏览器）；需要海外网络的官方接口（YouTube、TikTok） | 不保存权威状态 |
| **制作机**（`vk` CLI + Claude Code skill） | Mac mini | 把做好的作品入库；跑需要本机仓库的任务（官网：trustbridge 的构建与部署） | 不操作任何国内平台账号 |

**单机模式是默认值**：一台电脑同时承担三个角色，不需要服务器。分享给别人时就是这个形态。分布式只是配置，不是另一套代码。

### 2.2 状态只有一份，在云端

两台 Mac 不保存权威数据，所有读写都通过 HTTPS 调云端 API。命令已经只在 `commands.mjs` 定义一次，并派生出 HTTP 路由（三端一致律），所以 `vk --remote <url>` 只是换一种传输方式，不另写同步逻辑。三条铁律不变：零后门律对 Mac 同样适用，Mac 不直接碰云端的 SQLite。

### 2.3 活由机器主动来领

- 每台执行机器用**出站** HTTPS 长轮询领任务，不开任何端口，NAT 后面也能用。
- 领取沿用 BLUEPRINT §3.4 的语义：乐观锁、租约、30 秒心跳、租约过期重排、退避。原来是读本地 SQLite，现在改成调 API。
- 结果回报是幂等的（带 run id），状态迁移只在云端走 `transitionPublish()`。

### 2.4 账号绑定机器，任务按能力派发

- **每个账号绑定一台发布机**（`account.executor_id`）。云端只把这个账号的任务派给它，**发布机离线时不改派**，到了排期时间仍未上线就推飞书卡片"发布机离线"。这样"账号只在同一网络操作""Mac mini 不发小红书"都由代码保证。
- 不绑账号的任务按**能力**派发：每台机器上报自己能做什么（`browser`、`net:overseas`、`net:cn`、`repo:trustbridge`），任务声明需要什么。
- 用户当前的分配：

| 任务 | 跑在哪 | 原因 |
|---|---|---|
| 小红书、视频号、抖音、TikTok 的浏览器发布与采集；B站（biliup + 创作中心） | 发布机 | 和手机同网 |
| YouTube、TikTok 官方接口；抖音官方接口（权限批下来后） | 发布机 | 国内服务器连不上 YouTube、TikTok；抖音接口暂按同一处理 |
| 公众号草稿箱 | 云端 | 固定 IP 进白名单；国内网络 |
| 官网（assurelane.ai） | 制作机 | 要在 trustbridge 仓库里构建、部署（工厂现有做法） |
| LLM 分析、改写 | 云端 | Web 和飞书要能触发；火山方舟在同一家云上 |

### 2.5 文件：按内容哈希存放在云端，提前预取

- 实测（2026-11-15，从英国 Mac mini）：上传到 volc1 约 1.1MB/s；**从 volc1 下载约 0.11MB/s**，说明出口带宽很窄。
- trustbridge 现有成片 34 个，中位 8MB，最大 31MB，合计 0.4GB；一期全部版本约 100MB。
- 结论：**文件存 volc1**。33GB 可用空间够放几百期。下载慢通过预取解决：发布任务一排进日程，发布机就开始下载，到发布时文件已在本地。按此速度，一个 30MB 的成片要 4–5 分钟，一期全部版本约 15 分钟，后台跑可以接受。
- 文件按 sha256 寻址；发布机下载后先校验哈希再发布。所有平台都终结后 7 天删除云端副本，封面缩略图长期保留。
- 存储做成接口。如果发布机所在网络的实测速度也很慢，或者以后视频变大，就换成对象存储，不改其他部分。
- **待测**：发布机（美国）↔ volc1 的速度。另外，volc1 的带宽套餐可以在火山控制台查看或升级。

### 2.6 登录态从不离开发布机

- 平台凭证只在发布机的浏览器 profile 里，`credential_ref` 只记引用（BLUEPRINT D6 不变）。
- 要扫码时，发布机截下二维码传到云端，推送到飞书和 Web，用户用手机扫（复用 #101 的无头取码）。

### 2.7 接入与鉴权

- 云端地址：`vk.fangyouxi.cn` 指向 volc1，HTTPS。该域名的 DNS 在火山引擎；若备案不是在火山做的，要先在火山补办"新增接入"。
- 域名就绪前，两台 Mac 用 SSH 隧道连 volc1，开发不受阻。
- 每台设备一个令牌，按角色限权：制作机只能入库、查看；发布机只能领取绑定给它的任务、回报结果；Web 用户登录另外验证。令牌可在 Web 上吊销。
- 飞书长连接跑在云端（出站，沿用现有设计）。

## 3. 后果

**得到**
- 三台机器各干各的，每条约束都由代码保证，不靠人记。
- 手机上通过飞书看内容、点发布；云端常在线，Mac 合盖不影响查看。
- 单机模式保留，开源用户的上手门槛不变。

**付出**
- 多了一层网络：要处理断线、重连、租约过期、重复回报。
- 云端要运维：备份 SQLite、续证书、升级。
- 本地 Web 原来"只监听 127.0.0.1"的安全假设不再成立，云端 Web 要有登录和防爆破。

**不变**
- 命令注册表、状态机、事件模型、三条铁律、适配器契约。

## 4. 验证计划（通过后改为"已定"）

1. 单机模式下，用假适配器跑通"制作机入库 → 云端排期 → 发布机领取 → 回报 → 状态正确"，三个角色都在本机起进程。
2. 断线演练：发布机领取后断网，租约过期重排；恢复后重复回报，不会产生重复发布。
3. 绑定演练：账号绑定 A 机，B 机在线也领不到该账号的任务；A 机离线超过排期时间会推卡片。
4. 实测发布机 ↔ volc1 的下载速度，决定是否保留"文件存 volc1"。
5. 开发机保护：制作机（开发机）注册为 executor 时，不能绑定国内平台账号。
