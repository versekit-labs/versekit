# 项目约定与交付清单

## 找项目并确认一次

- 用 `git rev-parse --show-toplevel` 找当前工作目录的 Git 根，否则用 Claude 工作目录。Git 命令走正常 Bash 权限确认。
- 读根目录的 `.hifabu/project.json`。它是项目自己的数据，可以随项目提交，让 worktree、改名后的目录和同事共享同一个 `id`。Git worktree 当前分支没带该文件时，可从同一仓库已有 checkout 读取已确认的约定并沿用原 id。只复用属于同一仓库的文件，保留写入权限确认。
- 无已确认约定时运行 `hifabu --data "${CLAUDE_PLUGIN_DATA}" scan <项目根> --json`。扫描只看扩展名与修改时间，各类最多返回最近 100 项。结合文件名与用户在本轮指明的素材来猜，仅在需要时读取候选文案。交付使用选中的成片，读取元数据时不要用 Read 打开视频。截断时可在项目里用 Glob 补查用户点名的期。相对路径必须留在项目内。
- 用两三句话概括从哪里找成片、怎么选版本、封面及发布文案在哪，再用 AskUserQuestion 请用户确认这份项目约定。工具不可用就直接在对话中问并等待下一条回复。首次请求交付、点名素材和批准 Write 各是独立的动作。先得到用户对**项目约定**的明确同意，之后才调用 Write 创建文件，由 Claude 单独申请写权限。生成持久的随机 id，例如加 `p_` 前缀的 UUID。用户拒绝写入时说明约定未保存。
- 扫描结果只有一个视频时，把 `episodes` 保存为空对象 `{}`。这个分支即使文件名有编号也适用。路径或文件名里能认出期号时，`work.key` 用期号（如 `07`），不用 `works`，也不追问是哪一期；只有认不出期号，才用 `works` 记录用户确认的作品名和稳定标识。成片、封面和文案各在哪里，用 `notes` 写一句话记下，复交时按它直接找，已有约定就不再请用户确认。对已有约定的项目，用户点名的作品已有映射且成片唯一时直接复交。文件大小和修改时间不改变已明确的最高版本，报告时直接说明所选文件。不评价文件大小，不追问是否正式成片，不加发布前确认视频的提醒。

仅有一个视频且认不出期号时的项目约定示例（认得出期号的，`works` 可留空，key 取期号）：

```json
{
  "id": "p_a1e393cd",
  "name": "示例项目",
  "language": "zh",
  "episodes": {},
  "works": { "示例作品": "work_01" }
}
```

扫描发现多支视频且确有命名规律时的示例：

```json
{
  "id": "p_a1e393cd",
  "name": "示例项目",
  "language": "zh",
  "episodes": {
    "video": "成片/{episode}_{topic}*.mp4",
    "pick": "highest-version",
    "cover": ["封面/{episode}_{topic}_封面.png"],
    "copy": { "file": "文案/发布文案.md", "section": "## {episode} {topic}" },
    "notCopy": ["文案/*_文案.txt"]
  },
  "works": { "用户确认的作品名": "work_01" }
}
```

`episodes` 可用项目相对 glob 和占位符描述规律。可用 `notes` 记录用户确认过的素材特例，仅解释文件关系。这里不存账号组、账号、令牌或个人路径。只接受匹配 `^[A-Za-z0-9_-]{1,100}$` 的 id。`episodes` 为 `{}` 时，路径或文件名里认得出期号，稳定期标识就是期号（如 `07`），`work.key` 为 `<id>/07`；认不出期号才取 `works` 里的值，`work.key` 为 `<id>/<works 的值>`。首交和复交的 `work.key` 必须相同。项目后来加入更多期、改成有规律的 `episodes` 时，已交过的期仍用原来的稳定期标识（期号），不得因项目变大改 key；新加入的期用自己的期号。`episodes` 有规律时按期号取稳定期标识。没有期号则为确认过的名字新增作品标识并记入映射。最高版本按版本号数值比较。额外变体单列，同一变体重新交仍沿用该期标识。

## 账号组

- 先用 Read 检查 `${CLAUDE_PLUGIN_DATA}/projects/<id>.json`，再用 `group list` 核对快照。用已确认的 `.hifabu/project.json` 中的 id 构造路径，使用快照里的准确组名。
- 没有记录时建立项目默认组。单组直接选，多组用 AskUserQuestion 问一次项目默认用哪组，选项各包含组名和平台。问题只选择组名，直接回答某个组就足以确定项目默认组。收到回答后，下一步用 Write 把 `{"group":"准确组名"}` 保存到上述路径，用 Read 检查保存结果，然后才暂存或预览。Write 有单独的权限确认，成功后才能说已记住。用户拒绝写入时可用本次已选的组，并说明这次未保存。
- 已有有效记录时直接使用。用户在交付请求中主动说明「这期交到某组」时用该组完成本次交付，保留项目记录。用户主动说明「以后都交到某组」时，在核对后更新项目记录。首次回答选择题时只是组名，归入建立默认组的步骤。只要有快照且本次目标组已不在其中，就在预览和上传前停下，列出组名。若没有任何组，请用户去发布机配置。
- 时间戳 `reportedAt` 距今超过 24 小时，要说明平台来自旧快照。若 `reportedAt` 为空，告知发布机还没同步账号组，沿用记住的组或用户从发布机提供的准确组名。两者均无时请用户给组名。预览如果报告发布机不兼容，依错误参考处理。本轮只查一次组列表。

## 清单和暂存

向用户说明需要暂存的文件，使用正常权限确认。每次建独立的私有暂存目录（例如插件数据下的 `staging/` 子目录）；只暂存用户选定的文件。用文件名保留原始扩展名。优先复制，以便保留交付时的内容；常规的本机命令用 Bash 权限提示，参数用可靠引用方式。可用 `shasum -a 256`（macOS）或 `sha256sum`（Linux）及 `wc -c` 读取 SHA-256 和字节数。清单用 Write 保存，与暂存素材同目录。避免标题、选题和文案中出现本机路径。文件名、期标识含路径字符或 `..` 时使用安全的暂存名或稳定标识。不要让路径和项目文字另起 shell 指令。

内容结构：

- `schema` 为 `hifabu.delivery/1`，`work` 含 `key`（`<id>/<稳定期标识>`）、`title` 和可选 `language`。
- `cuts` 为数组，每支成片有 `video`，可附 `cover` 和 `copy`。文件对象为 `{name, sha256, size}`，`name` 只有文件名。文案示例见 [copy.md](copy.md)。
- `target` 为 `{group: "<选定组名>"}`，`from` 为 `{client: "hifabu-plugin/0.2.1"}`。清单不含其他本机数据；v1 中不要用旧的 `source` 字段。
- 预览与登记使用同一清单。暂存文件是后台上传的来源，应保留到发布机可以下载或本次已终结。不要提前删除，也不要为了查状态重新建清单或上传。

单支成片示例，实际填写所选的文件名、字节数和实测 SHA-256：

```json
{
  "schema": "hifabu.delivery/1",
  "work": { "key": "p_a1e393cd/02", "title": "示例选题", "language": "zh" },
  "cuts": [
    {
      "video": {
        "name": "02_示例选题_v3.mp4",
        "sha256": "154f2a8cef18b8adabe26d6a4828a055d657303188b88f8f890d125914a9b0f7",
        "size": 1048576
      }
    }
  ],
  "target": { "group": "示例组" },
  "from": { "client": "hifabu-plugin/0.2.1" }
}
```
